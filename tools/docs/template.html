Diki Design System

Diki's tokens and a complete set of utility classes, with role-based alias colors in six themes, Inter for type, Material Symbols Rounded for icons, and React components. Everything ships with the system: no outside fonts, scripts or frameworks.

How to use it

Build with aliases

Style screens with primary, text, border and the other aliases. Reach for a palette color like blue-600 only when no alias fits.

One name everywhere

A token's name is also its class suffix: blue-500 is bg-blue-500, text-sm, rounded-md and shadow-lg are classes, and in CSS every token is a variable: var(--blue-500).

Pick a theme

Use the theme menu in the sidebar. Alias swatches and live components on every page switch to that theme.

Click to copy

Click any swatch on this page to copy its CSS variable.

Start a page

<!doctype html>
<html lang="en" data-brand="blue" data-mode="auto">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <script src="components/theme.js"></script>          <!-- theme first: no flash -->
  <link rel="stylesheet" href="tokens.css">
  <link rel="stylesheet" href="components/base.css">     <!-- page defaults -->
  <link rel="stylesheet" href="components/bundle.css">   <!-- utilities and components -->
</head>
<body>…</body>
</html>

base.css sets page defaults from the tokens (body colors and font, no stray margins, one focus style, native controls in the theme's light or dark). Leave it out when dropping the system into an existing app. For production, trim bundle.css to the classes you use: python3 tools/purge.py src/ -o bundle.min.css takes it from 1.7 MB to a few dozen KB.

Themes

Six themes share one set of foundations: the same palette, type, spacing, radius, shadows and components. A theme only changes where the alias colors point. Switch with data-theme on any element, e.g. <html data-theme="violet-dark">.

Alias

Automatic dark mode

components/theme.js picks the theme for a page and follows the visitor's light or dark setting, live. Load it first in <head> so the page never flashes the wrong theme. A choice the visitor makes is remembered in their browser. Without the script, set data-theme yourself.

<html data-brand="blue" data-mode="auto">   <!-- brand: blue | violet | emerald · mode: auto | light | dark -->
<script src="components/theme.js"></script>

Diki.theme.set({ mode: 'dark' })      // a theme switcher; remembered
Diki.theme.set({ brand: 'violet' })
Diki.theme.reset()                    // back to the page's data-brand / data-mode
Diki.theme.onChange(({ theme }) => …) // e.g. "violet-dark"

Adding a theme

  • Pick a brand hue from the palette.
  • Give each alias a target in the new theme: copy a Light or Dark column and swap the brand hue.
  • Check on-primary on primary (4.5:1) and focus-ring on surface (3:1). Step one shade darker (light) or lighter (dark) if either fails.

Naming

  • <role> is the main color for a job: primary, surface, text, border.
  • -hover, -muted, -strong and -subtle are variants of the same job. -subtle is a light tint for backgrounds.
  • on-<role> and <role>-inverse go on top of that role, like on-primary text on a primary button.

Rules of thumb

  • Body text: text-base, font-normal. For long reading, add leading-relaxed.
  • Headings: font-semibold, with tracking-tight from text-2xl up.
  • text-5xl and larger have a line height of 1. Add leading-tight if a heading can wrap.
  • Keep body text at text-sm (14px) or larger.

Iconography

Icons are Material Symbols in the Rounded style with Fill on, weight 400, plus any custom icons you draw to the same rules. Use no other icon set or style. Click an icon to copy its name.

Setup

Nothing to load: tokens.css declares the icon font from fonts/.

const { Icon, Button } = window.Diki;
<Icon name="delete" />
<Icon name="error" aria-label="Error" style={{ color: "var(--danger)" }} />
<Button leftIcon="add">New project</Button>

Custom icons

For what Material Symbols doesn't have, add your own SVGs. They use the same Icon and Button props, sizes and colors as the font icons: <Icon name="diki-sparkle" />, <Button leftIcon="diki-sparkle">. A custom icon with the same name as a Material Symbol replaces it.

%%CUSTOMICONS%%

Draw

A 24×24 frame (viewBox="0 0 24 24") with about 2px of padding, filled shapes with rounded corners like the Rounded style, in one color. Parts that should show the background are holes, not white shapes.

Add

Put the SVG in assets/Icons/, named in lowercase with - or _ (diki-sparkle.svg), then run python3 tools/icons/build.py. It writes the icons into bundle.js and their names into the TypeScript types.

Safe by build

The build keeps only shapes, draws them in the text color and refuses anything else with the reason: scripts, links, images, text, gradients, masks, other grids or a second color.

Tested

The tests check the build, and that custom icons size, color, align, announce and load in buttons exactly like the font icons.

Guidelines

  • Icons follow the text color. Use text or text-muted for neutral icons and success, warning, danger or info for status.
  • Icons are decorative by default. Add an aria-label only when an icon carries meaning on its own.
  • Use one icon per meaning across the product: always delete, never delete in one place and remove in another.
  • The font loads with display=block, so icon names never flash as text while it loads.

Guidelines

  • Cap running text at max-w-prose so lines stay readable.
  • Dialogs: max-w-md by default, max-w-sm for confirmations, max-w-lg or max-w-xl for forms.
  • Page content: max-w-7xl centered, or .container.
  • Use min-h-dvh instead of h-screen for full-height mobile layouts.
  • Give flex and grid children that hold text min-w-0, so long words wrap instead of overflowing.

Guidelines

  • One dimension (a row of buttons, a toolbar, a stack) → flex. Two dimensions (cards, dashboards, forms) → grid.

  • Avoid order-* for content read in sequence: screen readers and keyboard focus follow the source order.

Pixel, text, skeleton and inverse

Text that shines

variant="text" is a loader made of words. They rest at 65% of the text color (still 4.5:1 on surface) while a band of full color sweeps through them every 2 seconds, easing in and out (ease-in-out). Screen readers hear them once, as the loader's name. Plain text under reduced motion. It stays in the text color: only inverse changes it.

Skeleton

variant="skeleton" draws gray shapes where the content will be, so the page doesn't jump when it arrives. shape="text" (default) draws lines as tall as the size's text line, the last of several 60% wide; "circle" is an avatar, the loader's size; "rect" is an image or card, full width and 96px tall. Set other sizes with className (w-48, size-12, h-40). The fill is the text color at 10%, with a lighter band sweeping through it every 2 seconds, like the text variant; a still fill under reduced motion.

Spokes

variant="spokes" is eight rounded spokes round a circle, like the iOS activity indicator. The lead spoke is at full strength and the ones behind it fade to 25%; the drawing ticks a spoke at a time, a full turn every second (--loader-spokes-duration). Under reduced motion it ticks at half speed.

Pixel

variant="pixel" is a 3×3 grid of square pixels in one color, edge to edge, split by hairline dividers (0.5px at 24px) in its color at 10%, which look the same whether the squares beside them are lit or dim. A wave of light runs along its diagonals from the top-left corner, each square rising from 15% to full and fading again, 75ms after the one before, in a 1.2s loop. With pattern="random" each square rises and fades on its own clock (1.5s to 2.2s), so they light up in an ever-changing order with no visible loop. Add glow for a soft halo of the same color (off by default; best on dark surfaces). It only fades, so it keeps running under reduced motion, at half speed.

Inverse for dark scrims

tone="inverse" makes the ring, spokes, dots, pixel grid, text or skeleton white in every theme, for scrims, overlays, photos and video, which stay dark. On surface-inverse, which turns light in dark themes, keep neutral.

Guidelines

  • Use radios for 2 to about 5 options people should compare; past that, a Select saves space.
  • Pick a default when one is safe, so the group never starts empty; leave it empty when the choice has to be deliberate.
  • Stack options; use a row only for short labels that fit on one line.
  • For on and off, use a checkbox or a switch, not two radios.

Switch

An on/off setting that takes effect at once. It's a native checkbox with role="switch", so screen readers announce "on" and "off", drawn as a track and a thumb that slides along it. The track sits on the label's first line, and the whole label flips it.

Guidelines

  • Use a switch for a setting that applies right away, like turning on Wi-Fi. If the change waits for a Save button, use a checkbox.
  • Label the setting, not the state: "Wi-Fi", not "Turn Wi-Fi on". The switch shows on or off.
  • Don't make the label change with the state, and don't add "On" and "Off" text beside it.
  • In a settings list, put the label first and the switch at the end of the row.
