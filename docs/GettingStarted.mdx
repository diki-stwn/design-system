# Getting started

## 1. Install

Install a released version straight from GitHub, pinned to its tag:

```sh
npm install github:diki-stwn/design-system#v4.8.0
```

Pin a tag, never `#main`, so updates reach your project only when you choose. The package builds itself as it installs. Until the first release tag exists, pin the latest commit on `main` instead (`#<commit>`).

**Updating:** change the tag and read the [Changelog](?path=/docs/changelog--docs) entries in between. Minor and patch releases never remove anything; major releases list what changed and how to migrate.

## 2. Use it in a React app

Vite, Next.js, Remix or any bundler. React 18 or later is a peer dependency, so the components use your app's React.

```js
import '@diki/design-system/tokens.css';
import '@diki/design-system/base.css';     // page defaults; skip it when adding the system to an existing app
import '@diki/design-system/bundle.css';   // or components.css, plus utilities.css if you use the classes
import { Button, Field, Input } from '@diki/design-system';

export function SignUp() {
  return (
    <form>
      <Field label="Email" required><Input type="email" /></Field>
      <Button type="submit">Create account</Button>
    </form>
  );
}
```

For router links, set the link component once at startup: `configure({ link: Link })`. The components render on the server too, and types ship with the package.

## Or on a plain page

```html
<html lang="en" data-brand="blue" data-mode="auto">
<head>
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <script src="dist/theme.js"></script>
  <link rel="stylesheet" href="tokens.css">
  <link rel="stylesheet" href="dist/base.css">
  <link rel="stylesheet" href="dist/bundle.css">
</head>
<body>
  <div id="root"></div>
  <script src="dist/lib/react.production.min.js"></script>
  <script src="dist/lib/react-dom.production.min.js"></script>
  <script src="dist/diki.iife.js"></script>
  <script>
    const { Button } = window.Diki;
    ReactDOM.createRoot(document.getElementById('root')).render(React.createElement(Button, null, 'Hello'));
  </script>
</body>
</html>
```

## 3. Pick a theme

`data-theme` on any element picks one of the six themes (`blue-light`, `blue-dark`, `violet-light`, `violet-dark`, `emerald-light`, `emerald-dark`). `theme.js` sets it on the page from `data-brand` and `data-mode`, follows the visitor's light or dark setting, and remembers a choice made with `Diki.theme.set()`. Load it first in `<head>` so the page never flashes the wrong theme. See [Themes](?path=/docs/foundations-themes--docs).

## 4. Before you ship

- **Trim the CSS.** `bundle.css` carries every utility class (1.7 MB). `tools/purge.py` in this repo keeps the component styles and only the classes your code uses, usually a few dozen KB. It isn't part of the installed package, so run it from a clone: `python3 tools/purge.py <your src> --css <installed dist/bundle.css> -o bundle.min.css`.
- **Fonts and icons are included.** `tokens.css` loads Inter and the icon font from the package's `fonts/` folder. Nothing loads from another server.
- **Accessibility comes with the components,** but labels are yours: give every field a `Field` label, every icon-only button an `aria-label`, and check each component's Accessibility notes.

## Working on the system

```sh
npm install
npm run storybook   # these pages, at http://localhost:6006, updating as you edit
npm test            # builds the package and runs every test, including axe in all six themes
npx changeset       # describe your change and pick patch, minor or major
```

Each component lives in `src/components/<Name>/`: the component (`<Name>.tsx`), its styles (`<Name>.css`), its component tokens (`<name>.tokens.json`), its usage guide (`README.md`, shown on its page here), its stories (`<Name>.stories.tsx`), its page (`<Name>.mdx`) and a `preview.html` for the visual tests. Its tests are in `tools/test/`. Write the usage guide from [the template](https://github.com/diki-stwn/design-system/blob/main/docs/usage-guide-template.md) (`docs/usage-guide-template.md`): when to use it, when not to, usage, accessibility, props and component tokens.
